# SignService — подписание документов ЭЦП

Отдельное настольное приложение на C# / [Avalonia UI](https://avaloniaui.net/) для подписания
документов электронной подписью (ЭЦП). Логика подписания портирована из сервиса
подписания документов ReportGGE:

- на Windows подпись создаётся **нативным CryptoAPI (`CryptSignMessage`)** — .NET
  `SignedCms` не умеет ГОСТ, а CryptoAPI отдаёт операцию криптопровайдеру сертификата
  (для ГОСТ — **КриптоПро CSP**);
- OID алгоритма хеширования выбирается по типу ключа: ГОСТ Р 34.10-2012 (256/512) →
  ГОСТ Р 34.11-2012, ГОСТ Р 34.10-2001 → ГОСТ Р 34.11-94, иначе SHA-256;
- в подпись вкладывается **вся цепочка сертификатов** (лист + УЦ + корень) — чтобы
  подпись проверялась офлайн; цепочка кешируется по отпечатку для пакетного подписания;
- по умолчанию формируется **усиленный формат CAdES-BES**: в подписанные атрибуты
  включаются время подписания (signing-time) и ссылка на сертификат подписанта
  (signing-certificate-v2, RFC 5035 — защита от подмены сертификата); certHash для
  ГОСТ-2012 сертификатов считается Стрибогом (ГОСТ Р 34.11-2012, управляемая
  реализация, проверенная на векторах RFC 6986), для остальных — SHA-256;
- выбранный сертификат **запоминается по отпечатку** — следующий запуск подписывает
  им же без повторного выбора.

## Возможности

- **Drag & drop** — перетащите файлы (или целые папки) прямо в окно программы;
- **Обзор** — добавление файлов через стандартный диалог выбора;
- выбор сертификата подписи из хранилища текущего пользователя («Личное»);
- **откреплённая** подпись — рядом с документом создаётся файл `имя_файла.sig`
  (формат, который требуют госпорталы и большинство систем документооборота);
- **прикреплённая** подпись — документ упаковывается внутрь `.sig`;
- пакетное подписание: очередь файлов со статусом по каждому файлу;
- **соподписание (объединение подписей)**: подписи других лиц объединяются с вашей
  в один `.sig` с несколькими подписантами —
  - если рядом с документом уже лежит `.sig`, ваша подпись по умолчанию добавляется
    к имеющимся (режим «Объединять с существующей .sig», отключается);
  - кнопкой **«＋.sig»** у файла (или перетаскиванием `имя_файла.sig` в окно) можно
    приложить подписи, полученные от других подписантов;
  - повторная подпись тем же сертификатом заменяет свою старую подпись, а не дублирует;
  - каждая объединяемая подпись **проверяется по хешу документа** (messageDigest из
    подписанных атрибутов; для ГОСТ — Стрибогом): подписи под другим файлом или
    прежней версией документа исключаются автоматически, с указанием подписанта
    в статусе — иначе портал отклонил бы весь контейнер;
  - объединение выполняется на уровне ASN.1 и работает в том числе для ГОСТ-подписей
    на любой платформе;
- **извлечение из криптоконтейнера** (кнопка «Извлечь из .sig…», поддерживаются
  `.sig`/`.p7s`/`.p7m`, в том числе base64/PEM и BER):
  - из прикреплённой подписи достаётся **вложенный документ** (байт-в-байт)
    и создаётся **откреплённая** подпись к нему со всеми подписантами;
  - контейнер с несколькими подписантами разбирается на **отдельные .sig
    по каждому подписанту** (имя файла содержит ФИО из сертификата);
  - существующие файлы не перезаписываются — при совпадении имён добавляется номер;
- фильтр просроченных сертификатов.

## Требования

- .NET 8 SDK (для сборки) / .NET 8 Desktop Runtime (для запуска);
- Windows с установленным криптопровайдером для ГОСТ-сертификатов
  (например, **КриптоПро CSP**) — подпись квалифицированной ЭЦП выполняется
  через CSP, привязанный к контейнеру закрытого ключа; при подписании может
  появиться системный диалог ввода PIN-кода;
- на Linux/macOS приложение также работает, но подписывает только сертификатами
  с алгоритмами, поддерживаемыми платформой (RSA/ECDSA); ГОСТ-криптография
  доступна только через CSP на Windows.

## Сборка и запуск

```bash
dotnet build SignService.sln -c Release
dotnet run --project src/SignService
```

Публикация самодостаточного однофайлового exe для Windows (не требует
установленного .NET на машине пользователя):

```bash
dotnet publish src/SignService -c Release -r win-x64 --self-contained true \
  -p:PublishSingleFile=true \
  -p:IncludeNativeLibrariesForSelfExtract=true \
  -p:EnableCompressionInSingleFile=true \
  -o publish
```

## Как пользоваться

1. Запустите программу — в выпадающем списке появятся сертификаты
   с закрытым ключом из хранилища «Личное» текущего пользователя.
2. Выберите сертификат и режим подписи (откреплённая/прикреплённая).
3. Перетащите файлы в окно или добавьте их кнопкой **«Обзор…»**.
4. Нажмите **«Подписать»** — рядом с каждым файлом появится `имя_файла.sig`,
   статус отобразится в списке.

## Структура проекта

```
src/SignService/
├── Services/
│   ├── CertificateProvider.cs   # доступ к сертификатам (X509Store)
│   ├── DocumentSigner.cs        # подпись CMS/PKCS#7: ГОСТ-OID, цепочка, кеш
│   ├── NativeSign.cs            # CryptSignMessage (CryptoAPI) — ГОСТ через КриптоПро
│   ├── CadesAttributes.cs       # атрибуты CAdES-BES: signing-time, signing-cert-v2
│   ├── CmsMerger.cs             # объединение/разбор подписей (соподписание) на ASN.1
│   ├── CmsExtractor.cs          # извлечение из контейнера: документ, подписи
│   ├── Streebog.cs              # ГОСТ Р 34.11-2012 для certHash (векторы RFC 6986)
│   └── AppSettings.cs           # запоминание сертификата и режима подписи
├── ViewModels/
│   ├── MainWindowViewModel.cs   # очередь файлов, команды подписания
│   ├── CertificateItem.cs
│   └── SignFileItem.cs
└── Views/
    └── MainWindow.axaml(.cs)    # UI: drag & drop, обзор, список файлов
```
